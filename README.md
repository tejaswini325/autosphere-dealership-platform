# AutoSphere — Dealership Platform

A full-stack MVP for the Isocode Software Engineering Intern take-home: vehicle discovery, city-wise on-road pricing, test-drive booking, lead management, admin inventory and AI-assisted sales replies.

## Stack
- React + TypeScript + Vite
- Java 21 + Spring Boot 3.4 + Spring Security + Spring Data JPA
- PostgreSQL 16
- Groq API (optional; deterministic fallback when no key is configured)
- Docker Compose for local PostgreSQL

## Quick start

### Prerequisites
- Node.js 20+
- Java 21
- Maven 3.9+ (or use an IDE with Maven support)
- Docker Desktop

### 1. Configure environment
Copy `.env.example` to `.env` in the project root. The default local database values work with the supplied Compose file. Add `GROQ_API_KEY` only if you want live AI drafts.

### 2. Start PostgreSQL
```bash
docker compose up -d db
```

### 3. Start backend
PowerShell:
```powershell
cd backend
$env:DB_URL="jdbc:postgresql://localhost:5432/autosphere"
$env:DB_USERNAME="autosphere"
$env:DB_PASSWORD="autosphere_local"
$env:JWT_SECRET="local-development-secret-change-this-to-at-least-32-characters"
$env:GROQ_API_KEY=""
./mvnw spring-boot:run
```
If you do not have the Maven wrapper, run `mvn spring-boot:run`.

Backend: http://localhost:8080
Health: http://localhost:8080/api/health

### 4. Start frontend
In another terminal:
```bash
cd frontend
npm install
npm run dev
```
Frontend: http://localhost:5173

## Demo accounts
The backend seeds these local demo accounts on first start:
- Buyer: `buyer@autosphere.demo` / `Buyer@123`
- Sales consultant: `sales@autosphere.demo` / `Sales@123`
- Admin: `admin@autosphere.demo` / `Admin@123`

Change these credentials before any public deployment. Demo data is synthetic.

## Main workflows
1. Browse seeded new and used vehicles and filter by type.
2. Open a vehicle and calculate its on-road price by city.
3. Request a test drive; slot uniqueness is enforced by the database.
4. Submit an enquiry; it is assigned to the seeded sales consultant.
5. Sign in as sales to view leads, update status and generate an editable AI reply draft.
6. Sign in as admin to add vehicles and update city price components.

## API overview
- `POST /api/auth/login`
- `GET /api/vehicles`, `GET /api/vehicles/{id}`
- `GET /api/pricing/{vehicleId}?city=Lucknow`
- `POST /api/bookings`
- `POST /api/leads`
- `GET /api/leads` (sales/admin)
- `PATCH /api/leads/{id}/status` (sales/admin)
- `POST /api/leads/{id}/ai-draft` (sales/admin)
- `POST /api/admin/vehicles` and `PUT /api/admin/pricing/{vehicleId}` (admin)

## Important implementation notes
- On-road prices are calculated from stored admin-configured components, never generated by AI.
- AI output is a draft only. It is never sent automatically. If `GROQ_API_KEY` is absent or the provider fails, the API returns a clearly labeled deterministic draft.
- Test-drive booking uniqueness is enforced for `(slot_id, demo_vehicle_id)` at the database level. A production deployment should additionally implement slot capacity/locking and expiry for abandoned reservations.
- JWT secret and database credentials are development defaults only. Use strong secrets in deployment.
- The sample images are remote Unsplash URLs; replace them with licensed dealership assets before production.
