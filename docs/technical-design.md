# AutoSphere — Technical Design

## 1. Scope
AutoSphere is a dealership workflow demo for the Isocode take-home. It includes vehicle discovery, city-wise price calculation, test-drive and service requests, trade-in requests, lead management, admin CMS and role management, plus AI-assisted sales support.

## 2. Architecture
- React + TypeScript + Vite frontend.
- Java 21 + Spring Boot 3.4 REST API.
- Spring Security with JWT role checks.
- PostgreSQL persistence through Spring Data JPA.
- Groq API is optional and called only from the backend. Deterministic fallback output is available without a key.

Browser → REST API → JWT/security and validation → controllers/services/repositories → PostgreSQL. The browser never receives the Groq API key.

## 3. Main data model
- `app_users`: account, password hash and role (`BUYER`, `SALES`, `USED_CAR_MANAGER`, `ADMIN`).
- `vehicles`: inventory, used-car inspection metadata, colours, masked registration and price validity.
- `city_prices`: per-vehicle/per-city tax, insurance and accessories.
- `test_drive_bookings`: vehicle/demo car, showroom, date, slot and consent; duplicate vehicle/date/time is rejected.
- `service_bookings`: workshop, date, time, service request and consent.
- `trade_in_requests`: current vehicle details, expected value and consent.
- `leads`: enquiry, assignment, status, consent, opt-out and simulated acknowledgement.
- `dealer_content`: offers and banners.
- `used_car_sales`: synthetic comparable sale records for manager-only price bands.

## 4. Business workflows
1. Buyers browse/filter new and used stock and open individual vehicle routes.
2. On-road pricing is calculated as ex-showroom + road tax + insurance + accessories from admin-configured city tables. AI is never used for prices.
3. Test-drive availability is checked against persisted bookings for a selected vehicle/date. The request also stores the showroom and customer consent.
4. Service requests are checked against a demo capacity of three per workshop/time slot.
5. Trade-in requests are persisted for follow-up; the demo does not automatically value or purchase a vehicle.
6. New web leads are assigned using showroom and used-car category rules. The record includes a simulated SMS acknowledgement and a five-minute age/SLA indicator.
7. Sales/admin can import legacy CSV leads, update status, request a buyer summary and generate an editable first-reply draft.
8. Used-car manager/admin can view a comparable-sales band based on synthetic historic sale rows.
9. Admin can create/update vehicles, update status and city price components, publish offers/banners and manage roles.

## 5. AI and safeguards
- Groq buyer summaries and first-reply drafts are optional.
- Fallbacks are deterministic when the API key is missing or the provider fails.
- First replies remain drafts; no send action exists.
- Prompts prohibit inventing prices, discounts, availability or promises.
- Used-car price ranges are calculated from persisted comparable sale records, not generated by the model.

## 6. Security and privacy
- Public endpoints are limited to buyer-facing read and submission workflows.
- Sales/admin and used-car manager/admin endpoints are role-protected.
- Buyer contact forms require consent; an opt-out endpoint marks matching leads as opted out.
- Demo accounts and records are synthetic. This is not a complete DPDP compliance implementation.

## 7. Explicit demo boundaries
- SMS/WhatsApp acknowledgement is simulated and no messaging/telephony provider is connected.
- Service capacity is a count check, not a concurrency-safe bay reservation with expiry.
- Test-drive requests are not confirmation of real showroom/demo-car availability.
- CSV importer expects simple unquoted comma-separated rows.
- Historical used-car sale data is synthetic.
- Hindi/English localization, production performance certification, SEO prerendering/SSR, payment processing and DMS integration are not complete.
- Real dealership operation requires production identity controls, audit logs, rate limiting, monitoring, backups, secure secrets, retention/deletion workflows and verified business data.
